# Domuz Design System — 資料デザイン共通ルール

> 株式会社Domuz の資料（外部営業・投資家/銀行向け・社内）を **1つのデザインシステム** で統一するための基準書。
> 新しく資料を作るとき・既存資料を直すときは、まずこのファイルを読む。
> 機械可読な値は同じフォルダの [`tokens.json`](./tokens.json) にあり、この文書と常に同期させる。

- バージョン: **1.0.0**（2026-09-16）
- 元にした資料: 会社概要（2025-07）／LY様 フラワーギフト提案（2026-08）／Gipt様 提案（2026-08）／giftee様 ミモザ提案（2026-08）
- ビジュアルの基準ブランド: **AND PLANTS**（ロゴ色 `#004347` を主色に採用）
- 更新手順は最下部「[更新のしかた](#更新のしかた)」参照

---

## 0. ひとことで言うと

**「白と生成りの余白に、AND PLANTS の深い緑をひと筆。英数字は幅広のジオメトリックサンセリフ、日本語は太い見出しでメリハリ。」**

- 明るい紙面（白／生成り／薄いグレー）が面積の 80% 以上。深い緑は "締め" にだけ使う（暗くなりがちなので面積で使わない）
- 見出しは **日本語を大きく太く**、英語は **小さくトラッキング広め** に添えてハイライトのように見せる
- 項目・カードの背景は **ニュアンスのある生成り（ベージュ）／グレー**、角丸 10pt
- 文字だけのスライドを作らない。**必ず写真・ロゴ・図・数字のどれかが入る**
- 游ゴシックは使わない

## 1. カラー

主色は AND PLANTS ロゴの深緑。元資料から実測した値をそのまま採用し、暗くなりすぎる問題は「面積」と「明るいアクセント（ミント）」で解決する。

### 1.1 プライマリ（グリーン系）

| トークン | HEX | 用途 | 由来 |
|---|---|---|---|
| `green-900` | `#002B2F` | セクション区切り・クロージングの全面背景。**面積で使えるのはこの用途だけ** | 会社概要・LY 提案の区切りスライド |
| `green-800` | `#004347` | 見出し文字、強調文字、バッジ背景、グラフの第1系列、表の1列目 | **AND PLANTS ロゴ実測色**／Gipt・giftee 提案の見出し |
| `green-500` | `#598487` | 英語の小見出し（eyebrow）、キャプション、表のラベル | Gipt 提案のキャプション |
| `green-200` | `#A5BCBE` | 濃い背景の上の補助線・サブテキスト | Gipt 提案 |
| `green-100` | `#DFE7E7` | 表のヘッダー行、淡い区分の背景 | Gipt 提案 |
| `mint` | `#00D79C` | **1資料に1〜2箇所だけ**の明るいアクセント（表紙の短いライン、アクティブ状態、選択中プラン） | giftee 提案の表紙ライン |

### 1.3 アクセント

| トークン | HEX | 用途 | 由来 |
|---|---|---|---|
| `coral` | `#E16464` | 金額・本数などの **強調数字**（営業資料）。結論の1語 | Gipt 提案の価格 |
| `coral-deep` | `#C94F4F` | coral の文字を小さく使うとき（可読性確保） | Gipt 提案 |
| `hanaichi-yellow` | `#F8BA00` | ハナイチ ブランド色。グラフの第2系列、ハナイチ関連のバッジ | ハナイチ ロゴ／会社概要の売上グラフ |
| `highlight` | `#FFF59A` | 表のヘッダー行のハイライト（Gipt 提案の `#FFFF79` を目に優しく調整） | Gipt 提案 |

### 1.4 使い方の比率（目安）

- 白／生成り／グレー地：**80%以上**
- `green-800` 文字・小物：10〜15%
- `green-900` 全面：区切りスライドのみ
- アクセント（coral／mint／yellow）：**5%以下**。1スライドに強調色は1種類まで

### 1.5 やらないこと

- 純黒 `#000000` の文字（`ink-900` を使う）
- グラデーション、影付きの派手な立体
- 緑を面積で使う（区切り以外）
- 1スライドに coral と yellow と mint を同時に置く

## 2. タイポグラフィ

### 2.1 フォント

| 役割 | 第1候補 | 代替（無い環境） | 備考 |
|---|---|---|---|
| 英字・数字（本文〜見出し） | **Century Gothic**（Pro） | Futura／Jost／Poppins／URW Gothic | 会社概要・LY・giftee 資料で実使用 |
| 英字ディスプレイ（表紙・区切りの大文字） | **Europa Bold** | Century Gothic Bold | 会社概要「PLATFORM VISION」等で実使用 |
| 日本語 | **ヒラギノ角ゴシック（Hiragino Sans）** W3 本文／W5 小見出し／W6 見出し | Noto Sans JP（Regular/Medium/Bold） | Mac 標準。Windows・Google スライドでは Noto Sans JP を入れる |
| **使わない** | 游ゴシック／Yu Gothic／MS ゴシック／メイリオ／Aptos | | 指定フォントが無いときの自動置換にも注意 |

- **英字・数字は必ず Century Gothic**（日本語フォントの英数字をそのまま使わない）。数字の並ぶ表・グラフ・KPI は特に徹底
- 英字は **大文字＋広いトラッキング** が基本（見出し・ラベル・キャプション）。文章としての英語だけ通常の字間

### 2.2 サイズと字間（4:3・幅 10 インチ基準）

| 要素 | サイズ | ウェイト | 字間 (charSpacing) | 色 |
|---|---|---|---|---|
| 表紙タイトル（日） | 34–40pt | W6 | +2pt | `green-800` |
| 表紙タイトル（英・大文字） | 40–48pt | Bold | +6〜8pt | 白（緑地）／`green-800` |
| 区切りスライド見出し（英・大文字） | 36–44pt | Bold | +8〜12pt | 白 |
| スライドタイトル（日） | 24–28pt | W6 | +1.5〜2.5pt | `green-800` |
| eyebrow（英・小・大文字） `- OUR BUSINESS -` | 9–10pt | Regular | +3〜4pt | `green-500` |
| 英語サブタイトル（日タイトルの横 or 下） | 8–9pt | Regular／Bold | +3〜4pt | `green-500`（強調なら `coral`） |
| 小見出し（日） | 13–15pt | W6 | +1pt | `green-800` |
| 本文（日） | 11–12pt | W3 | 0〜+0.5pt | `ink-700`、行間 1.5–1.7 |
| KPI 数字 | 32–48pt | Bold (Century Gothic) | 0 | `coral` or `green-800` |
| KPI 単位・ラベル | 9–11pt | Regular | +1pt | `gray-500` |
| キャプション | 8–9pt | Regular | +2pt（英） | `gray-500` |
| ヘッダー／フッター | 7–8pt | Regular | +2pt | `gray-500` |

### 2.3 タイトルの組み方（日英併記のメリハリ）

日本語を主役に、英語は **小さく・大文字・字間広く** 添える。3パターンのみ使う。

```
A) eyebrow 型（中央または左）        B) 横並び型                       C) 下付き型（表紙・重要ページ）
   - OUR BUSINESS -                     ■案A  祭壇形式  ALTAR STYLE        国際女性デー
   運営サービス                          （バッジ＋日タイトル＋小英字）        ミモザギフト 企画のご提案
                                                                          INTERNATIONAL WOMEN'S DAY / MIMOSA GIFT
```

- eyebrow は必ず `- ` と ` -`（半角ハイフン＋スペース）で挟む。例：`- Our Growth -`（先頭大文字）または全部大文字。1資料内で統一
- 英語サブタイトルは日本語タイトルの **1/3 以下のサイズ**
- タイトル下にアクセント線を引かない（余白で区切る）

## 3. レイアウト・スペーシング

### 3.1 判型
- **既定：4:3（10 × 7.5 in）**。既存資料がすべて 4:3 のため。16:9 が必要な場合は `tokens.json` の `layout` を `wide` にする（各値は幅比で自動スケール）

### 3.2 グリッド
| 項目 | 値 |
|---|---|
| 外側マージン | 0.55 in（上下左右） |
| ヘッダー行 | y = 0.30 in：左「Domuz inc.」／右「Confidential」（外部資料のみ） |
| フッター行 | y = 7.10 in：左「Copyright (C) Domuz inc, All Rights Reserved.」／右 ページ番号 |
| タイトル領域 | y = 0.60〜1.45 in（eyebrow ＋ タイトル） |
| コンテンツ領域 | y = 1.65〜6.85 in |
| 列間（gutter） | 0.25 in |
| カード内パディング | 0.25 in |
| 要素間の最小間隔 | 0.20 in |

### 3.3 角丸
| 対象 | 半径 |
|---|---|
| カード・ボックス | 10pt |
| 写真 | 8pt（フルブリードは 0） |
| バッジ（`PLAN 1`／`案 A`） | 4pt |
| 人物写真 | 円（正方形をトリミング） |

### 3.4 余白の考え方
- 埋めない。1スライドの情報は「見出し＋3ブロック」まで
- 同じレイアウトを3枚以上続けない（カード→写真＋テキスト→表→図…と交互に）

## 4. コンポーネント

### 4.1 スライドの種類（この中から選ぶ）

| **Cover B – ミニマル** | 白地、左寄せ。eyebrow `PROPOSAL` → 日タイトル（`green-800`）→ 英サブ → mint の短いライン（幅 0.7in）→ 日付・担当 → サービスロゴ | 営業提案の表紙（写真主体の資料） |
| **Section divider** | `green-900` 全面、中央に英大文字（白・字間 +10pt）、下に日本語（`green-200`・9pt） | 章の切り替え |
| **Title + Cards** | タイトル A 型、下に 2〜3 枚のカード（`beige-100`／`gray-100`、角丸 10） | サービス紹介・比較 |
| **Photo + Facts** | 写真 2〜4 枚（角丸 8）を上、下に生成り／グレーのファクトボックス（`[面積]` `[場所]` のラベル） | 拠点・設備 |

| **Table** | ヘッダー行 `green-100`（または `highlight`）、1列目 W6 `green-800`、罫線 `gray-200` 0.5pt、行高 0.45in 以上 | 比較・料金・会社概要 |
| **Profile** | 左に写真（正方形または円）、右に名前（日＋英小）、肩書（`green-500`）、本文。経歴は円形ステップ（`beige-100`）＋矢印 | 代表・メンバー |
| **Flow / Diagram** | `beige-100` の大きな下地に白ボックス（角丸 6）＋矢印。強調枠は `coral` 1.5pt | 事業構造・バリューチェーン |
| **Logo wall** | 白地にロゴを等間隔グリッド（高さ揃え）、上に KPI 1 個 | 投資家・取引先 |
| **Closing** | `green-900` 全面、社名・URL のみ（または Cover A の変形） | 最終ページ |

### 4.2 バッジ
- 角丸 4pt、`green-800` 地に白文字、9–10pt、Century Gothic Bold、字間 +1pt、高さ 0.28in
- 例：`PLAN 1` `PACKAGE` `案 A` `参考 ①`
- 淡い版：`green-100` 地に `green-800` 文字（参考・補足用）

### 4.3 カード
- 背景 `beige-100`（温）または `gray-100`（冷）。同一スライドでは混ぜない
- 枠線なし・影なし。区別が必要なら `taupe-400` 0.5pt の枠か、`beige-200` に濃度差
- 中身：ラベル（9pt `gray-500`）→ 値（数字は coral／green）→ 補足（10pt `ink-700`）
- **強調カード**は `green-900` 地・白文字（LY 提案「Full-Custom」）。3枚のうち1枚まで

### 4.4 注記ボックス
- 「※ ご留意点」など：白地・`green-500` 1pt 枠・角丸 8。または `beige-200` 塗り
- 注記文は 9–10pt `ink-700`。「※」は全角

### 4.5 表
- ヘッダー：`green-100`（投資家向け）／`highlight`（営業向けの比較表）
- 1列目：W6・`green-800`、`gray-100` 塗りにしてもよい
- 罫線：横のみ `gray-200` 0.5pt。縦線は引かない
- 数字は右揃え・Century Gothic。強調数値だけ `coral`

### 4.6 グラフ
- ネイティブ（編集可能）で作る。画像貼りは禁止
- 色順：`green-800` → `hanaichi-yellow` → `green-500` → `sand-300`
- 軸ラベル・データラベル：Century Gothic 9pt `gray-500`。データラベルは末尾値と節目のみ
- 凡例はロゴで置き換えてもよい（会社概要のスタイル）
- 目盛線は横のみ `gray-200`。枝線・外枠なし

### 4.7 ヘッダー／フッター
- 外部資料：ヘッダー左「Domuz inc.」右「Confidential」、フッター左コピーライト、右ページ番号
- 社内資料：ヘッダーは省略可。フッターのページ番号は残す
- 表紙・区切りにはフッターのみ（またはなし）

## 5. 写真・イラスト（AIっぽく見せないために）

### 5.1 原則
- **すべてのコンテンツスライドに写真・ロゴ・図のいずれかを入れる**
- 素材は `design-system/assets/` の **自社写真** を最優先。無い場合は自社で撮る／既存 EC の商品写真を使う。汎用ストック写真・AI 生成画像は使わない（参考イメージとして使う場合は「※AI生成によるイメージ画像です」を必ず添える）
- 写真は **白背景の物撮り**（AND PLANTS の商品写真トーン）と **現場写真**（ハウス・倉庫・手元）の2種を混ぜると資料に体温が出る
- 人物は正面・自然光・目線あり。円形トリミング

### 5.2 配置
- 角丸 8pt、同じ列内で高さを揃える
- 写真の下にキャプション：英大文字（字間 +2pt）＋日本語 の順。例 `WRAPPING  ラッピング`
- フルブリード（裁ち落とし）は表紙・区切りの背景として1資料に1〜2回まで

### 5.3 イラスト・アイコン
- 線画または単色の平面イラスト。色は `green-800`／`green-500`／`mocha-700` のいずれか1色
- 花・植物・箱・家・人のシンプルなピクトグラム（LY 提案の配送フロー図のトーン）
- 3D、グラデーション、影付きアイコン、絵文字は使わない

### 5.4 ロゴ
- AND PLANTS ロゴ：`green-800` 単色版を白／生成り地に。最小幅 0.9in
- ハナイチ ロゴ：黄色シンボル＋黒文字のフルカラー版のみ。白／`beige-100` 地に
- 他社ロゴ（投資家・取引先）：白地に等高で並べる。色は変えない

## 7. 文言・表記

## 9. ファイル構成と使い方

```
design-system/
  DESIGN_SYSTEM.md   ← この文書（人が読む基準）
  tokens.json        ← 色・文字・寸法の値（プログラムが読む基準）
  assets/logos/      ← AND PLANTS・ハナイチ・投資家ロゴ
  assets/photos/     ← 自社写真（商品・拠点・メンバー）
.claude/skills/domuz-deck/
  SKILL.md           ← Claude Code に資料を作らせるときの手順
  lib/theme.js       ← tokens.json を読み、pptxgenjs でこのシステム通りの部品を描く
  lib/postprocess.py ← 日本語フォント（ヒラギノ）の埋め込み・検証
  templates/         ← スライド種類ごとのサンプルコード
decks/
  <資料名>/build.js  ← 各資料のソース。output/ に .pptx と PDF
```

Claude Code で資料を作るとき：`/domuz-deck 会社概要をアップデートして` のように依頼すると、この文書と tokens.json を読み込んだ上で組んでくれる。手で PowerPoint／Keynote／Google スライドを作る場合もこの文書の値をそのまま使う。
