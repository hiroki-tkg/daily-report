# Domuz デザインシステム v2.1 — 配布パッケージ（社内メンバー向け）

小松（AND PLANTS / AND FLOWER 事業責任者）と同じ品質の **提案資料** と **発表スライド** を、Claude Code で作るためのパッケージです。分析レポートの雛形も入っています。

最終更新: 2026-09-30

---

## いちばん大事なこと: 提案資料と発表スライドは別物

| | 提案資料 | 発表スライド |
|---|---|---|
| 用途 | 他社・法人向けの提案、営業資料、見積・プラン | 社内発表、合宿、締め会、経営MTG |
| 読まれ方 | 相手が手元で読む・社内回覧される | プロジェクターで全員が見る |
| 1枚の情報量 | 多くてよい（表・写真・注記で完結させる） | 1枚1メッセージ（話して補う） |
| 本文の文字 | 12〜14px | 25〜31px（タイトル38px・大数字76〜85px） |
| 見せ方 | 表・写真・料金表・フロー図 | グラフ（前年比較・積み上げ・ドット図） |
| 雛形 | `templates/proposal.template.html` | `templates/presentation.template.html` |
| 中身の作り方 | `guides/提案資料の作り方.md` | `guides/発表スライドの作り方.md` |

同じ4:3のスライドでも、雛形を取り違えると「文字が小さくて読めない発表」「情報が足りない提案書」になります。Claudeに頼むときは、必ずどちらかを明言してください。

## 中身

| ファイル | 役割 |
|---|---|
| `domuz_design_system.md` | 本体。色・フォント・レイアウト・型カタログ（提案資料 B-1〜B-25／発表スライド P-1〜P-14）・禁則・PDF手順・チェックリスト |
| `guides/提案資料の作り方.md` | 提案資料の種類と構成、事前に集めるもの、表現の癖、禁止事項、送付・訂正メールの型 |
| `guides/発表スライドの作り方.md` | 発表の進め方（位置づけ→一本の筋→構成→数字→HTML）、構成の型、言葉の選び方、数字とグラフのルール |
| `templates/proposal.template.html` | 提案資料の雛形（10枚の型見本）＋プレビューPDF |
| `templates/presentation.template.html` | 発表スライドの雛形（14枚の型見本）＋プレビューPDF |
| `templates/presentation_charts.py` | 発表スライド用のグラフ（SVG）生成ヘルパー。Claudeが使う |
| `templates/report.template.html` | 分析レポートの雛形（縦スクロール・A4縦PDF）＋プレビューPDF |

まずプレビューPDF（`*.preview.pdf`）を開くと、それぞれの型の見た目が分かります。

## 導入（5分）

1. このフォルダを自分の作業ディレクトリにコピーする
   例: `~/work/.claude/knowledge/design_system/`
2. 自分の `CLAUDE.md`（作業ディレクトリ直下）に次を追記する

```markdown
## デザインシステム（提案資料・発表スライド・レポート）
視覚的なアウトプットをHTMLで作るときは、必ず `.claude/knowledge/design_system/domuz_design_system.md` を読む。
**提案資料と発表スライドは別物。雛形も型も混ぜない**（違いは同文書 §0-1）。
- 提案資料（他社・法人向け・手元で読む）→ `templates/proposal.template.html`＋§6（B-1〜B-25）＋ `guides/提案資料の作り方.md`。最終ページは会社概要
- 発表スライド（社内発表・合宿・締め会・プロジェクター投影）→ `templates/presentation.template.html`＋§6-2（P-1〜P-14）＋ `guides/発表スライドの作り方.md`。グラフは `templates/presentation_charts.py` でSVG生成
- 分析レポート → `templates/report.template.html`
- 色はCSS変数のみ（HEX直書き禁止）、4:3・1128×846px、PDF併産、納品前に §10 のチェックリスト
- 保存: 種類別フォルダ（提案資料／発表スライド／分析レポート）の中を `html/` と `PDF/` に分け、ファイル名は日付先頭 `YYYYMMDD_テーマ`
```

3. 動作確認
   - 提案資料: 「〇〇様向けのグリーンレンタル提案資料をHTMLで作って（提案資料）」→ 表紙・ヘッダ・会社概要が出ればOK
   - 発表スライド: 「来週の締め会の発表スライドをHTMLで作って（発表スライド）」→ 左端のライトグリーン帯・大きい文字・グラフが出ればOK

## Claudeへの頼み方（コツ）

**提案資料**
- 相手先・提案の段階（初回商談／回答／現地調査後のプラン／改定版）・先方のメールや要望を最初に渡す
- 写真・見積・現場メモがあれば添える。無ければ「写真は後で差し替え」でプレースホルダーのまま進めてもらう
- 例:「〇〇様、現地調査後の初回プラン。拠点は2つ、要望は『葉色が濃いもの』。見積はこのPDF。提案資料で作って」

**発表スライド**
- 自分の持ち時間・前後の発表者・聞き手を最初に伝える
- 「一本の筋」を一緒に決めてから、構成→数字→HTMLの順に1段ずつ進める（いきなりHTMLを作らせない）
- 例:「合宿で15分、自部署の前期振り返りと今期方針。まず内容のたたきを考えて。発表スライドで」
- 数字は「売上は送料込み・税抜」「利益は広告費込み限界利益」と伝えると定義のズレが減る

## フォント

- 提案資料・レポート: 欧文 Century Gothic Pro（Adobe Fonts。未導入ならFuturaに自動切替）＋和文 Hiragino Sans（macOS標準）
- 発表スライド: Outfit＋Zen Kaku Gothic New（雛形がGoogle Fontsから読み込むので導入不要。オフラインだとヒラギノ等に切り替わる）

## PDF化

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --no-pdf-header-footer --print-to-pdf="出力.pdf" "file:///絶対パス/入力.html"
```
Claudeに「PDFも出して」と言えば実行します。PDFは全ページを画像にして目視確認してもらってください。

## ルール

- 色・フォントの正は Figma「AND PLANTS スタイルガイド」。変更提案は小松まで
- 雛形の `:root` の変数は書き換えない。型やクラスを足したら `domuz_design_system.md` の型カタログに1行書く
- 提案資料の会社概要（従業員数など）は使う前に最新を確認する
- 社外秘の数字を含む資料は、配布・送付の前に宛先と中身を確認する
