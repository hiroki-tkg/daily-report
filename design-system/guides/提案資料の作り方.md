# 提案資料の作り方（小松泰彦の型）

> 対象: 他社向け提案資料（HTML→PDF）を Claude Code で作る社内メンバー
> 前提: 見た目・トークン・型カタログは Domuzデザインシステム v2（domuz_design_system.md）と templates/ の雛形が正。本ガイドは「中身の組み立て方と表現の癖」を扱う。

---

## 1. 提案資料の種類と標準構成

共通の土台
- 形式は HTML スライド（4:3・固定キャンバス 1128×846px を JS でウィンドウ幅にスケール）→ PDF 併産。aspect-ratio だけで伸縮させると文字がはみ出して崩れる。
- 画像は base64 埋め込みの単一 HTML（1ファイル送れば相手も同じ表示）。PDF は `@page` をスライドと同寸にして Chrome headless `--print-to-pdf --no-pdf-header-footer` で出力。
- 雛形から作る。ゼロから組むと余白・字間・装飾が再現できず「らしくない」と判定される。直近で評価の高かった資料の `<style>` の数値をそのまま移植するのが最速で正確。
- 15枚を超えそうなら、本当に必要なページか見直す。

| 種類 | 使う場面 | 標準構成（並び順） | 入れない／注意 |
|---|---|---|---|
| A. 初回商談向け（サービス概要型） | 先方が「まずサービス内容を聞きたい」段階。設置場所・数量が未確定 | 表紙（宛名入り）→ 01 ABOUT US（運営サービス〜拠点）→ 02 サービス説明（特徴・導入フロー4ステップ・料金）→ 03 APPENDIX（関連する別サービス紹介）→ 会社概要1枚（必ず最終ページ固定） | 2空間比較ページ、仮の数量を置いた料金シミュレーション、導入期間の日数（「最短◯週間」等）、タイムライン図 |
| B. 回答特化型（初回の企画・実現可能性回答） | 先方から具体的な質問・企画相談が来た時 | 表紙 → 回答サマリー → 前提（花材・仕様等）→ 選択肢 → 比較 → 想定単価 → 会社概要 | 章扉、企画の全体像、自社の強みページ、特典設計・ボリュームディスカウント・値下げ余地などの先走り要素 |
| C. 現地調査後の初回プラン | 現地調査を経て置き場・品種・数量が決まった時 | 表紙 → 全体像 → 01 拠点A → 02 拠点B → 03 お見積・条件 → 会社概要 | 同一顧客の複数拠点は担当者が別でも1本にまとめる。お見積は拠点を列にした1枚の表＋リード文で拠点別内訳 |
| D. 店舗向け（買取・リース・販売型） | 店舗に植物を置き、販売・リースを組み合わせる時 | 表紙 → 提案サマリー → 植物リスト一覧表（品種・数量・設置場所・参考EC価格）→ サイズ別写真カード → 販売形態・運用スキーム → お取引条件（買取／リース比較表）→ 品種別価格試算 → 導入スケジュール | 鉢カラー列は不要。既存取引先なら会社概要は不要（新規先には入れる） |
| E. 商品（企画）提案 | ギフト企画・季節商品などを写真で見せる時 | 表紙 → 1企画=1スライド（写真2枚: 例 ラッピング＋花瓶）→ 荷姿（梱包写真2枚＋箱サイズ cm）→ 会社概要 | 3企画を1枚に詰める（写真が小さくなる）、装飾的な形容・キャプション |
| F. 予算縮小の改定版 | 初回案に対し先方から予算上限が示された時 | 5ページ程度: 表紙 → 全体像 → 植栽写真 → 内訳＋サイズ別単価表 → 条件 | フル資料の再発行、選定方針の説明枠、スケジュールページ、配置図（本数が大きく減ったら「現地で優先度の高い場所をご指示ください」方式へ） |
| G. 季節装飾・過去シーズン商品の紹介 | 取引先にクリスマス等の季節商品を提案する時 | 「設置場所×サイズ」の順に6点程度: 卓上単品 → 卓上セット → 中型ツリー → 大型シンボルツリー → 壁面（リース）→ 卓上アレンジ。各商品は「番号＋商品名＋用途1行」 | 過去シーズンの価格（書くなら「参考価格（過去シーズン）」と明記） |
| H. 実績紹介 | 過去実績をまとめて見せる時 | 事実の一覧 → 本筋でない情報は【参考】／APPENDIX として末尾 | 実績タイムライン頁の追加、「継続実績の証明」的な演出 |

料金ページの型（A・C 共通）
- 料金表は「サイズ／高さの目安／月額（税抜）」の3列。右に「月額に含まれるもの（✓4点程度）」と「ご契約条件（最低期間・最低金額＝応相談）」の2ボックス。
- 単価は品種ではなくサイズで決まる体系なので、サイズ別単価表を1枚入れておくと、現場で品種変更・本数追加をそのまま巻き取れる。
- 打ち消し線で「◯円〜 → 応相談」と見せる割引演出は使わない。

## 2. 作る前に聞く・集めるもの

ヒアリング項目
- 先方の段階: サービス概要を知りたいのか、具体的な質問への回答が欲しいのか、見積が欲しいのか（→ 1章の種類を決める）。
- 先方がメール・資料で使った項目立て（サイズ区切りか、設置場所区切りか等）。資料の情報の区切りは先方の構造に合わせる。自分で再編すると差し戻しになる。
- 予算上限・数量・期間（期間限定か継続か）・拠点数と各担当者。
- 先方の要望キーワード（例:「葉色が濃いもの」）。品種カードに「ご要望との対応」として書く。
- イベント・装飾案件では、スペースの広さより先に会場の設置レギュレーション（サイズ制限・ゾーン設置の可否・防炎）。これで形態ごと覆ることがある。
- 画面共有で投影するのか、送付して読んでもらうのか（投影なら文字を約1.3倍に）。
- 宛名を入れるか（汎用の概要資料は宛名なしが基本。案件ごとに確認）。

実現可能性の確認（社内が先）
- 仕組みや新しい運用を提案に入れる前に、まずエンジニア・制作チームに実現可能性を確認する。先に約束して後から作れないのが最悪パターン。
- エンジニア相談の型: 案件概要 → 背景 → 要件イメージ（仮）→ 確認したいこと（作れるか／工数感／方式のおすすめ／注意点を番号付き）→ スケジュール感と「初期は簡易版でOK」→「厳しければ別方式にするので率直に」。方式は指定せず選択肢で聞く。
- 花の制作物（リース・アレンジ等）を植物案件に混ぜる時は、受注前に花チームに制作可否を確認する。

写真の集め方
- 商品写真は全品 3:4 で撮影されている。掲載は aspect-ratio 3/4・object-fit: contain（トリミング禁止）。
- EC画像は Shopify の商品メディアのファイル名規則（handle・鉢・色・番号）で「品種×サイズ×鉢色」まで一致するものを探せる。過去シーズン品（EC非公開）は Admin 検索で DRAFT／ARCHIVED も含めて引く。
- 他メンバーが作った承認済み Google スライドがあれば、そこから写真と配置図を抜くのが最速（手動修正済みの鉢色・形が保てる）。品種との対応はスライド内の x 座標順で取り、2〜3枚目視で検証してから全量採用。図形で描かれた配置図は PNG エクスポートで取得。
- メンバーから受け取った写真は品種の取り違えを疑い、受け取った時点で「品種の特徴・鉢の形と色が指定と合っているか」を目視確認。鉢色が指定と違う等の違和感は取り違えのサインなので一言添えて確認する。
- 写真が未撮影でも資料は先に完成させる。未撮影枠は破線ボックスのプレースホルダー「〇〇（撮影後に差し替えます）」で埋め、届き次第差し替え。

価格・見積・サイズの集め方
- 高さの表記は ①現場担当（品種選定者）のメモ → ②商品ページの「高さの目安」（Shopify メタフィールド）の優先順。サイズ区分の一般目安は使わない。
- サイズ区分（L/M等）の解釈は現場担当の表記が正。途中で変わることがあるので、変わったら「バッジ・高さ・お見積の本数・全体像の合計・メール本文の金額」を連動させる（生成スクリプトを1本持つと崩れない）。
- 見積書（見積システムの番号付きPDF）は税込計算になっていることがある。単価体系は税抜が正なので資料は税抜で揃え、見積書は再発行を依頼する。未修正なら見積書は添付しない。
- 価格・条件の根拠は、前例のない企画なら机上でなく小規模試作の実測（1本あたり工数・資材単価）で作る。既存相場の外側の案件は参照点がない＝弱気に既存相場へ寄せない。

既存資料の流用
- 最終的にレンダリングで見えているものが正。ファイル内部のテキストではない（旧スライドの画像を新テキストの上に全面貼りして隠しているケースがある）。テキスト抽出とスライド画像の両方を取り、食い違えば見えている側を採用。
- 情報パリティを守る: 変換・リメイク時にリード文・日付・補足説明を勝手に足さない。デザインは変えてよいが情報は足さない・引かない。特に価格・契約条件は、元資料の見た目に無ければ裏データにあっても載せない。
- APPENDIX に別資料を入れる時はページ範囲を数字で指定されることが多い。似た名前の資料が複数あるので、元PDFを必ず特定してから着手。本編と重複するページは除外してよいが、その旨を報告する。
- 数値ラベルのないグラフは再描画しない（AIが棒の高さを読み取ると仮説が混入する）。元PDFから高解像度クロップして貼る。
- 他人の資料は説明文のコピペミス（別品種の説明）と価格の桁誤りを必ず疑う。
- 「デザインシステムあってる？」は色HEXの一致ではなく「直近で評価の高かった資料と流儀が揃っているか」の意味。作り直す前に、本当にズレているかを実測してから判断する。

## 3. 構成・表現の癖（修正指示で繰り返し求められたこと）

事実だけで組む
- 元データにある事実だけを載せる。営業的な演出（タイムライン追加、「継続実績の証明」的なフレーミング、調達実績の強調）は足さない。演出を足したい時は提案として分けて聞く。
- 理由・根拠を推測で作らない。例:「ホワイトグレー統一（1鉢のみブラック）」の注記に「樹の印象に合わせて」のような理由を付け足さない。

テキストは最小限
- 1回目から装飾語を入れない。削除指示が出たもの: 表紙の宛名行（商品提案時）、「ボリューム重視／たっぷり束ねて」等の形容、箱の説明、画像下キャプション。企画名＋構成＋価格で足りる。
- ラベル語彙の例: 花材構成は「セット内容」ではなく「花材内訳」。本数は 0.5本単位でそのまま書く（1.5本 等）。
- 検討中は「（案）」「概算・調整中」等の保険文言を入れてよいが、先方送付版では全部削る。社内検討用の行（参考の年間合計など）も最終版では消す。

断定の度合い
- 単価は初回では「想定単価（イメージ）」とし確定値にしない。
- 一方で制約・リスク（色が混ざる、視認性、上限がある等）は数字込みで正直に書く。期待値ギャップ（先方想定の数量と実際に可能な数量の差など）は資料でぼかさず、数字で早めに潰す。
- 旬のもの（季節の花材等）の納期は3段で期待値調整: ①例年ベースの見込み → ②「時期が近づいたら産地状況を見て再確認」→ ③エンドクライアントには幅を持って伝えてもらう。断定せず、曖昧にもしない。
- 環境適性は正直に注記する（例: 本来屋外向きの品種は「入口付近など明るい場所での短期間の展示に向いています」）。売りたさで伏せると後で信頼を失う。

価格の見せ方
- 金額はすべて税抜で統一し「（税抜）」を明記。
- 初回提示ではボリュームディスカウントを入れない（交渉余地として温存）。
- 納品・設置費、契約満了時の回収、付属品（キャスター付き受皿等）は月額込みにし、お見積に行を立てない。
- 変動しうる品目（一点もの等）は行を立てず表の下に「※ ◯は△の単価で計上。選定する植物により月額が変わることがございます」と注記。一点もの枠は上位サイズの単価で見積もっておく（下振れの方が交渉しやすい）。仕上がりが微妙な候補写真は載せず「一点ものをいくつかお持ちし、現地で最適な植物を選定」の注記カードにする。
- 過去シーズン商品の価格は書かない。「今年の仕入れ状況により価格・仕様は変わる可能性があります」「ご希望があれば今年の内容でお見積り」の2文で受ける。
- 中間パートナー経由の案件では、仕入れ値・原価・パートナー取り分の率や内訳を資料にも文面にも一切載せない（「◯◯様分を含めた金額」まで）。

期間・頻度・日付
- メンテナンス頻度は明言しないのが基本。書く場合も「◯回程度」と必ず「程度」を付ける。低月額の案件では記載自体を消す（枯損交換は当社負担＝訪問頻度は当社の品質管理であって先方への約束ではない）。運用フロー図のメンテ項目にも回数は書かない。
- 導入フローに日数を書かない（初回商談向け）。
- 運用フロー（スキーム）ページには具体日付を書かず、日付はスケジュールページと条件ページに集約。
- 期間限定案件は「最低契約期間」ではなく「契約期間は◯年◯月末まで」と書き、「ご契約の更新により継続も可能」を必ず添える（門を閉じない）。月途中の開始・終了は日割り。

予算縮小・断りの扱い
- 予算上限を示されたら、予算内ぴったりの1案で返す。複数案・増額説得はしない。増枠の芽は「サイズ別単価表＋本数追加・品種変更は単価で承ります」で置いておく。
- やりたくない事項は「先方判断の帰結」として因果で説明し、「見送り」とは言わず「立ち上がりを拝見しながら改めてご相談」で保留締め。

レイアウトの癖
- 見出し位置は全ページ上揃えで統一（上下中央寄せが混ざると余白が気になると指摘される）。上揃えにしてカード側を大きくして埋める。
- 投影用で崩れたら「写真を縮める → 文言を短くする → タイトルのカナ表記を削る」の順で吸収。特徴カードは写真の縦幅を優先（情報量は写真が担う）。
- 品種提案カードには「先方ご要望との対応」を書くと選定理由が伝わる。
- グラフは可能ならSVGで描き直す（成長を見せるなら縦長）。
- 写真の鉢色が指定と違っても、撮影済みのものしかない新商品ならそのまま使ってよい。

## 4. やってはいけないこと（チェック項目）

- [ ] 隠れ他社情報: 流用元ファイルの下層（隠れたテキスト・貼り付けPDF）に旧クライアント名や特別条件が残っていないか。見つけたら成果物に含めず、「下に◯◯が埋まっていた。生かす意図はあったか」を依頼者に報告する（隠れ側が最新の意図の可能性もある）。PDF／HTML化して渡すと残留情報の流出を構造的に防げる。
- [ ] 見えているものが正: テキスト抽出だけで内容を確定していないか。
- [ ] 情報を足していないか（リード文・日付・補足・演出・推測の理由）。
- [ ] 元資料の見た目に無い価格・契約条件を裏データから載せていないか。
- [ ] 仮の数量を置いた料金シミュレーションを初回に出していないか（数字が独り歩きする）。
- [ ] メンテ頻度・導入期間・具体日付を不要な場所に書いていないか。
- [ ] 税込と税抜が混在していないか（見積書由来の税込に注意）。
- [ ] 仕入れ値・原価・パートナー取り分が文面・資料に出ていないか。
- [ ] 数値ラベルのないグラフをAIが描き直していないか。
- [ ] 写真と記載の不一致: 花材・本数・品種・鉢色が写真と合っているか（相手は「3案で量が同じに見える」「◯◯のみなのに別の花が写っている」まで見る）。閉じた箱の写真に配送伝票・ケアマークが写り込んでいないか。
- [ ] 他人の資料由来の説明文コピペミス・価格の桁誤り。
- [ ] 現場メンバーの口頭宣言（例: 契約水準を超える訪問頻度）が資料・運用に紛れ込んでいないか。
- [ ] box-shadow を使っていないか（Chrome PDF で四角いグレーになる。デザインシステム禁則とも一致）。
- [ ] `transform: translateY(-50%)` で縦中央揃えしていないか（PDFでページ分断する。flex で揃える）。
- [ ] 一覧表の行数が多い時、最終行（合計行）が overflow で消えていないか（画面では気づけないのでレンダリング画像で確認）。
- [ ] 送付済みの資料を上書きしていないか（訂正は別ファイル）。

## 5. 送付・訂正・リマインドの型

提案送付メール
- 初めて名乗る時: 「株式会社Domuzで◯◯の責任者をしております◯◯と申します」。返信が遅れた時は冒頭にお詫びを1行。
- 構成: ①添付資料の案内＋内容の箇条書き（4点程度）→ ②選定の考え方（先方要望の尊重＋代替提案の断り＝安心材料）→ ③懸念潰し（搬入制限クリア等）→ ④日程打診。
- 金額・条件は本文に書かず資料参照に留める（金銭は最後）。例外として、初回プラン送付では「■ご提案概要」に拠点別月額と合計（税抜）を短く示してよい。
- 変動要素は「現在バイヤーが産地で選定中」のように進行中の動きを添えると前向きに伝わる。締めは「ご要望があれば調整いたします」。
- 日程打診は「初回納品から逆算すると◯月◯旬までに確定できると安心です」と期限の根拠を添え、先方に候補日を出してもらう。
- 認識齟齬が予想される時は、齟齬ポイント（スペース・単価感など）を送付文で前出しし「お早めにすり合わせを」と伝える。
- 文面と資料の役割分担: 写真・価格・企画名は資料、お届け時期・条件・座組の含みは文面。資料にあることを文面で繰り返さない。
- 宛先: 既存スレッドに途中から入る時は既存CCを維持した全員返信。スレッドがバラけた案件は新規スレッドで関係者全員（各拠点担当＋紹介元）を To、社内関係者を CC。
- 細部確認型の相手から番号付きの確認が来たら、番号1対1で回答する（まとめない・順序を変えない）。ミスは言い訳せず認める（「誤って使ってしまいました。撮り直します」）。

商談後フォロー
- 商談当日中に: お礼＋投影資料PDF＋エシカルポリシーPDF（法人先には毎回添える）＋現地調査の候補日（5枠程度・移動込み2〜4時間枠・「別日でも可」の逃げ道）＋図面・現場写真の事前共有依頼。
- 日時確定の返信は最小限: 日時・場所の復唱＋到着時の連絡方法1行＋図面依頼の再掲。同行者は明言しない。情緒的な前置きは削る。

リマインド（超軽量）
- 挨拶 →「先日お送りした◯◯の件、ご検討状況はいかがでしょうか？」→「ざっくりの感触だけでもいただけると助かります」→「ご不明点や認識の齟齬などあればお気軽に」→ 締め。5行以内。論点再掲・期限プレッシャーは載せない。

訂正（リマインド兼用）
- 送付済みの資料は上書きしない。訂正は別ファイルで作る（命名例: `{相手先}様_{テーマ}_{訂正日YYYYMMDD}_訂正版.pdf`）。原本は「何を送ったか」の証跡として残す。修正前に必ず作業前バックアップを取る。
- 訂正メールは元の送付スレッドへの返信で出す。構成: 訂正内容（どのページの何か）→ 差し替え資料と素材単体の添付 →「写真以外の内容・お見積金額に変更はございません」と影響範囲を明示 → お詫び1行 →「ご検討状況はいかがでしょうか」＋「気になる点・ご要望があればお気軽に」。

社外文面の頻出チェック
- 自分側の落ち度に「ご」を付けない（「こちらの連携不足」）。
- 「ご確認いただけますと幸いです」（可能形）。
- 断り＋新規依頼を1通に入れる時は「せっかくご提示いただいたのですが」等の感謝クッションを挟む。
- 同一スレッド内で「様」「さま」を混在させない。
- 先方担当と社内メンバーが同姓の時は、本文でその社内メンバーに触れない。
- 締めに「お祈りします」は使わない。
- 手直しされて送られた文面は、送信済み本文と差分比較して何が削られたかを学ぶ。

## 6. 納品前チェックリスト

1. 資料の種類（1章 A〜H）に合った構成か。不要ページ（章扉・強みページ・シミュレーション等）が残っていないか。会社概要は最終ページ固定か（既存取引先の店舗向けは不要）。
2. 情報の区切りが先方のメール・資料の項目立てと一致しているか。
3. 元データ・元資料にない情報（演出・推測の理由・裏データの価格条件）を足していないか。
4. 金額はすべて税抜・「（税抜）」表記で統一。見積書・メール本文・資料の金額が一致しているか。
5. サイズ・高さ・本数・合計・メール金額の5か所が連動しているか（現場担当の最新表記に合わせたか）。
6. メンテ頻度・導入期間・具体日付の書き方がルール通りか（頻度は原則書かない／書くなら「程度」）。
7. 仕入れ値・原価・他社名・他社向け特別条件が一切出ていないか（隠れ層も確認）。
8. 写真と記載（品種・鉢色・花材・本数）が一致しているか。写り込み（伝票・ケアマーク）はないか。
9. 検討用の保険文言（（案）・概算・調整中）や社内用の行を削ったか。
10. 装飾語・キャプション・形容を削ったか。見出しは全ページ上揃えか。
11. デザインシステム v2 準拠（CSS変数のみ・HEX直書きなし・4:3 1128×846・影なし）。§10 チェックリストも通したか。
12. PDF を全ページ画像化して目視したか（ページ分断・表の最終行欠け・フォント代替を確認）。
13. PDF のページ数＝スライド数、ファイルサイズがメール添付できる範囲か（画像は長辺 1,100px 程度・JPEG q85 目安で再エンコード）。
14. ファイル名に相手先・テーマ・日付が入っているか。送付済みファイルを上書きしていないか。生成スクリプトと素材を永続フォルダに残したか（一時フォルダは次セッションで消える）。
15. 送付メールが5章の型に沿っているか（金額は資料参照・宛先/CC・齟齬ポイントの前出し）。
