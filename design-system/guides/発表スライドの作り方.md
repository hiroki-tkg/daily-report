# 発表スライドの作り方（小松泰彦の型）

> 対象: 社内発表・合宿・締め会・経営MTG用のスライドを Claude Code で作る社内メンバー
> 見た目は `domuz_design_system.md` §0-1・§6-2 と `templates/presentation.template.html` が正。本ガイドは「中身の組み立て方と進め方」を扱う
> 手本: 締め会デッキ（2026年3Q・Google Slides）、1Day合宿スライド（2026-10-09・15分・32枚）

---

## 1. 提案資料との違い（最初にここを確認）

- 発表スライドは**プロジェクターで全員に見せる**。話し手が横にいるので、スライドは「1枚1メッセージ」で文字は大きく、説明は口頭で足す
- 提案資料の雛形（ヘッダ・カード・小さい本文）で作ると、情報が多すぎて文字が読めない。**必ず `presentation.template.html` から作る**
- 数字は羅列せずグラフにする。グラフは `presentation_charts.py` で作る

---

## 2. 進め方（この順で、1段ずつ合意を取る）

1. **位置づけを決める**: 自分の前後に誰が何を話すか。重なるテーマ（全社PL・ビジョン）は他の人に預け、自分の役割を1行で書く
2. **一本の筋を決める**: 聞いた人に持ち帰ってほしい1行（例:「前期は売上重視から利益重視へ考え方を変えた年。今期はそれを保ったまま売上も伸ばし黒字化する年」）。これを冒頭に置く
3. **パート分けと比較軸**: 3パートが基本（前期の振り返り／今期に向けて／自分たちがやる価値・意味）。前期はYoY、今期は計画比、のようにパートごとに軸を決めて混ぜない
4. **概要をNotionに書く**: 構成・時間配分・決定済みの前提・要確認リストを1ページに。候補段階のメモは、確定したら消して確定情報だけ残す
5. **トピックを選ぶ**: 過去の締め会資料・データから候補を理由付きでリスト化し、発表者が選ぶ。選ぶ基準は「一本の筋を補強するか」「今期の方針に繋がるか」「全員が自分ごとにできるか」の3つ。各チームが締め会で発表済みの個別成果は主語が散るので外す
6. **数字を取る**: 下の「数字のルール」に沿って、BigQuery・シートから実数を取る。取れない数字は「算出中」の枠を置いて先に進む
7. **スライド構成を1枚ずつ書く**: 各スライドの「見出し／載せるもの／グラフ／口頭で話すこと」を表で決める
8. **HTMLで作る → PDF化 → 全ページを画像で目視**: はみ出し・重なり・グラフの数値ラベルを確認
9. **修正の往復**: 指摘は1回で全部反映し、ページ番号を振り直してPDFを再出力する

---

## 3. 構成の型（15分・約30枚の例）

| パート | スライド（型ID） |
|---|---|
| 導入 | 表紙（P-1）→ 一本の筋（P-2） |
| 前期の振り返り | 章扉（P-3）→ 利益 年次（P-4）→ 利益 月次（P-5）→ 売上 年次（P-4）→ 売上 月次（P-5）→ 変えたこと（P-2）→ 記録（P-6）→ タイムライン（P-7）→ トピック1枚ずつ×6（P-8・P-9） |
| 今期に向けて | 章扉 → 自事業の役割の図 → 選択肢（P-2）→ 計画の数字（P-10）→ 3本柱（P-11） |
| 価値・意味 | 章扉 → 届けた数 → レビューの星 → お客さんの声×6（P-13）→ まだ余地がある（P-12）→ ラストメッセージ（P-14） |

- 年次の積み上げ（セグメント別）の直後に、月次の前年比較（合計）を置く
- タイムラインで羅列してから、主要トピックを1枚1テーマで深掘りする
- 最後に冒頭の筋を繰り返すまとめスライドは要らない。ラストメッセージで終わる

---

## 4. 言葉の選び方

- **締めは前向きに**。「必達」「燃料」のような義務・手段の言葉より、「達成できると会社の未来が飛躍的に開ける」「まだまだ無限の可能性がある」「大変なことも多いけど頑張ろう」
- **話の順番は感情の流れ**: 成果 → 届いた人の満足 → それでも余地がある → 呼びかけ
- 主張文は1枚に1〜2文。キーワードだけライトグリーン
- 課題は1行ずつ淡々と。自責の話を別の枠でやるなら、発表側で先出ししない
- 補足の統計（例: 植物の保有率）は、流れを止めるなら注記に回す

---

## 5. 数字のルール

- **売上は送料込み・税抜**。シート・BigQueryの「税抜売上」は送料を含まないことが多い。BigQueryの送料欄（`item_subtotal_shipping_price`）は税込なので÷1.1して足す
- **利益は広告費込み限界利益まで出す**。イベント（母の日・初売り）も売上だけで終わらせず、「対象商品の限界利益−そのキャンペーンの広告費」で広告費込みを出す
- **期間を揃える**: 前年比較は両年とも同じ日付範囲（例: 10/1〜9/28）
- **締め会資料とBigQueryは基準が違うことがある**。YoYを出すなら両年とも同じソースで
- **グラフの主張文は書く前に検算**（例:「4・5月は大きく上回った」→ 実際は4月+4%だった）
- **推計を含む数字**（広告費データが無い月など）は注記に「推計」と方法を書く
- 合計と内訳が一致しない理由（共通広告費など）は注記に書く

---

## 6. グラフのルール

- 全体（単系列）＝Moss Green、前年＝グレー、強調＝ライトグリーン
- セグメントは AND PLANTS＝ライトグリーン／AND FLOWER＝ピンク `#EF667D`／モール＝Moss Green
- 月次×セグメントの積み上げは見にくいので使わない。月次は合計の前年比較、内訳は年次の積み上げ
- 数値ラベルはすべての棒に（月次は当年だけでよい）。単位は左上
- 規模感はドット図（400個中1個）、割合は人型・マス（10人中3人）で見せる

## 7. 納品前チェックリスト

1. `presentation.template.html` 起点か。提案資料のヘッダ・フッタ・カードが混ざっていないか
2. 1枚1メッセージか。本文25px以上、15px未満は注記だけか
3. 数字をグラフで見せているか。色が6章どおりか
4. 売上は送料込み・税抜か。期間が揃っているか。推計の注記があるか
5. 主張文を全データで検算したか
6. ページ番号が振り直されているか
7. PDFを全ページ画像化して目視したか（はみ出し・重なり・タイムラインの点の二重表示など）
8. ファイル名が日付先頭 `YYYYMMDD_テーマ`、`html/` と `PDF/` に分けて保存したか
